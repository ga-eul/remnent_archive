## 1. 에셋 운용 원칙 (기본 토대 + 점진 교체)

현재 `인트라넷 UI/` 폴더의 이미지는 **기본 토대**다. 이후 조금씩 교체·추가하는 것을 전제로 만든다.

1. **글자를 이미지에 넣지 않는다.** 문구는 코드에서 `dialogue.md` 원문을 넣는다. 글자가 박힌 시안(`오프닝용 문구.png`, `오프닝용 문구2.png`, `독백.jpg`)은 참고용이고, 실제로는 글자 없는 틀(`오프닝용.png`, `기본 대화창.png`)과 배경(`독백 페이지.jpg`)을 쓴다.
2. **화면은 코드로 만들고 이미지는 재료로만 쓴다.** `사내 인트라넷.jpg`, `사내 메신저 창.jpg`, `사원정보.jpg`, `사원증.jpg`는 완성 시안이므로 보고 HTML로 다시 짠다. 건물 사진·아이콘·래미 얼굴 같은 재료만 이미지로 쓴다.
3. **에셋 목록 한 곳.** 화면별 이미지 경로를 에셋 목록 파일 하나에 모으고, 코드는 목록만 참조한다. 교체는 같은 이름으로 덮어쓰거나 목록 한 줄만 고친다.
4. **임시 화면 우선.** 단서 자료 이미지(03-A~06-G)·직원 사진·약도 그림은 미정(`decisions.md` 4절 7번)이므로 텍스트 카드·실루엣으로 먼저 만들고 나중에 교체한다. 교체해도 화면 배치가 깨지지 않게 이미지 칸의 크기를 고정한다.
5. **공통 디자인 값.** 남색 배경 + 민트색 강조, Noto Sans KR / JetBrains Mono를 인트로 허브와 함께 쓴다 (D18).

## 2. 6단계 계획

### 1단계. 기반 설계 — 뼈대·데이터·저장

- **목표**: 그림 없이 페이지 01~07이 버튼으로 넘어가고 저장·복원되는 빈 뼈대.
- **범위**
  - 폴더 구조: `shinip/`(CASE 01), `assets/`(에셋 목록 포함), `data/`

  - 페이지 전환은 플레이어 버튼으로만 (R-03), 자동 페이지 전환 금지
  - 허브 약속: `remnant.global` status(`none`/`in_progress`/`finished`), `remnant.present-01` 진행 저장·복원 (R-80~R-85)

- **선행 결정**: 기술 방식 (4절 10번)

### 2단계. 오프닝·입사 — 페이지 01

- **흐름**
  1. 허브 [입사하기] → `오프닝.jpg` PC 바탕화면 (A.M. 9:00)
  2. 알림 "어서오세요" (`오프닝용.png` 틀 + 글자) → ▶ 클릭

  4. 바탕화면 [인터넷] 아이콘 → 고액 채용 공고 → 이력서(이름 필수, 비우면 ‘신입사원’)
  5. 바탕화면 [사원증] 아이콘 → 아바타 사진 선택 → 사원증 발급 (`사원증.jpg` 시안)

- **완료 기준**: 이름·아바타·사원번호 DA-A가 사원증, 사원 정보 창, My Archive, 업무 기록, 06-B, 엔딩 2·3까지 이어진다 / 화면 어디에도 ‘실험용’ 없음 (D13)
- **선행 결정**: 독백 문구·채용 공고 문구 원문(`dialogue.md`에 추가) / 바탕화면 아이콘 사용 순서

### 3단계. 인트라넷 셸·래미·메신저·보안 퍼즐 — 페이지 02

### 4단계. 조사 시스템 — 수색 1·2, 심문 (페이지 03~05)

#### 4-1. 수색 화면 (수색 1·2·3 공통 틀, `수색1 예시.png` 구조 참고)

```
STEP 0n · SEARCH                         (단계 라벨)
수색 1                                    (제목)
안내 문구: 약도에서 장소를 고르고, 조사할 수 있는 곳을 눌러 단서를 찾으세요. 출입이 통제된 곳은 다음 수색에서 열립니다.
┃ 상황 문구 박스 (시각 + 현재 상황 1~3문장)
SITE MAP  REMNANT ARCHIVE 사내 약도                 확보한 자료 n
┌──────────┬──────────┬──────────┐
│ 기록보관실 │ 관제실     │ 생활공간   │   ← 열린 장소: 장소명 + "확보 n"
├──────────┼──────────┼──────────┤
│ 업무실험실 │ 제한구역   │           │   ← 닫힌 장소: 흐리게 + "출입 통제"
└──────────┴──────────┴──────────┘
```

- **장소 칸**: 장소 5곳만 (R-01). 칸을 누르면 그 장소 안의 조사 지점 목록 → 자료 열람 → 증거 보관함에 추가
- **규칙에 맞춘 변경 (예시와 다른 점)**
  - 예시의 "EVIDENCE 11 / 20", "단서 11 / 11"처럼 **전체 개수를 보여 주지 않는다** (R-30, 7절 "총량 숨김"). 확보한 수만 표시: 상단 "확보한 자료 n", 장소 칸 "확보 n"
  - 장소 칸에 "조사 완료" 표시도 하지 않는다 (남은 자료 유무를 알려 주는 것과 같으므로)
  - 표시명에 결론 금지 (R-32)
- **층·배치**: 장소 5곳의 층·위치는 미정. 처음에는 위 격자로 만들고 약도 그림이 정해지면 교체 (에셋 원칙 4)
- **수색 단계별 열림**

| 수색 | 페이지 | 열린 장소 (열람 자료) | 출입 통제 | 다음으로 |
|---|---|---|---|---|
| 수색 1 | 03 | 기록보관실(03-A), 관제실(03-B), 생활공간(03-C) | 업무실험실, 제한구역 | 03-A·B·C 확보 → [면담 시작] (R-12) |
| 수색 2 | 05 | 기록보관실(05-A), 관제실(05-B-VHS·05-B-PERSONNEL ‘복구된 기록 자료’ 묶음, 05-E), 업무실험실(05-A 확보 후 개방 — 05-C → 05-D), 생활공간(선택 탐색) | 제한구역 | 필수 7개 → 제한구역 개방 (R-20) |
| 수색 3 | 06 | 제한구역(06-A, 06-B, 06-D/E, 06-S 선택) + 이전 장소 재방문 (R-21) | — | 06-A 열람 → [최종 추론] (R-22) |

- **상황 문구 박스**: 수색별 1~3문장. 원문은 `dialogue.md`에 추가 필요. 날짜·시각은 15절 날짜 규칙을 따르고, 다음 CASE의 정답을 담지 않는다 (검수 질문)

#### 4-2. My Archive (= 증거 보관함, D23)

My Archive는 **획득한 단서 열람 + 단서 조합 시스템**이다. 인트라넷 홈의 My Archive 카드(총 n건)를 누르면 열린다.

1) 기본 My Archive
```
┌─────────────────────────────┐
│ MY ARCHIVE                  │
│                             │
│ [전체] [문서] [CCTV]        │
│                             │
│ ┌──────┐ ┌──────┐ ┌──────┐ │
│ │문서  │ │CCTV  │ │문서  │ │
│ │출입  │ │복도  │ │업무  │ │
│ │기록  │ │영상  │ │기록  │ │
│ └──────┘ └──────┘ └──────┘ │
└─────────────────────────────┘
```

2) 단서 조합 영역
```
┌──────────────────────────────┐
│        단서 조합              │
│                              │
│  [출입 기록]    +    [CCTV]  │
│                              │
│              ↓               │
│          [ 조합하기 ]         │
│                              │
│       새로운 단서 해금        │
└──────────────────────────────┘
```

3) 조합 성공 시 예시
```
              ▼
       ┌─────────────┐
       │ NEW         │
       │             │
       │ 출입자 명단  │
       │ 4XXX.04.12  │
       └─────────────┘
```

- **목록**: [전체] / [문서] / [CCTV]. 획득한 단서만 카드로 보인다 (R-30). CCTV = 03-B, 05-B-VHS. 그 밖의 자료(명부·일기·면담 기록·실험 기록·로그·보고서)는 문서
- **조합**: 획득한 단서 카드 2장을 조합 영역에 드래그앤드롭(모바일 탭) → [조합하기]. 순서 무관 (R-35). 오답은 ‘연관성을 찾을 수 없습니다’, 회색 처리, 패널티 없음 (R-37). 조합 횟수 제한은 없지만 같은 두 자료 조합은 한 번만 시도 가능, tried_pairs에 있는 조합은 다시 조합할 수 없다 (R-37a, D26)
- **조합 성공**: 일반 조합 8개(C01·C04·C05·C06·C07·C08·C10·C11)의 결과가 "NEW" 카드로 해금된다 (D24·D25). 카드 내용은 `case01-logic.md` 6절 추론 결과 문장, 카드 이름은 6절 NEW 카드 이름 표(「두 자료 + 대조 기록」, R-32). C13은 일반 NEW 카드로 다루지 않고 My Archive에 저장하지 않는다. 화면 구성은 5단계 C13 최종 추론 모드(D28~D30). 엔딩 3 판정 조건에는 그대로 포함. NEW 카드는 [전체]·[문서]에 들어가고, 다시 조합 재료로 쓰지 않는다. 엔딩 판정 로직은 그대로. 카드에 날짜·시각이 필요하면 `4XXX.04.12 09:17` 형태
- 위 예시의 카드 이름("출입 기록", "출입자 명단")은 화면 예시이며 CASE 01 실제 자료명이 아니다
- 상단 수치 "획득 자료 n / 연결 성공 n / 현재 단계" (R-31), 총량 숨김. 홈 카드 "총 n건"도 획득 수. "연결 성공 n"은 일반 조합 8개의 성공 수이며 C13은 포함하지 않는다 (D31)
- 연결 대상: C01(튜토리얼), C04, C05, C06, C07, C08(05-D 열람에 따른 단계적 갱신, D17), C10, C11 / C13은 최종 추론 후 C13 연결 단계에서만 (그 밖의 조합은 잠금, R-51)
- 래미 관찰 기록 저장 (R-38), 최종 추론 이후에도 열람 가능

```

안내 문구: 수색 1에서 확인한 기록으로 질문할 수 있습니다. 받은 진술은 면담 기록에 남습니다.
```

- **직원 목록**: A·B·C 세 명, 사진·이름·담당·진행 막대·상태(진행 중 / 완료 / 잠김)
- **규칙에 맞춘 변경 (예시와 다른 점)**
  - **순서 고정 A → B → C** (R-13): 앞 직원 완료 전에는 다음 직원 잠김. 예시처럼 아무나 고를 수 없다
  - **질문은 Q1~Q4 고정 버튼**. 예시의 "기록을 들이밀면 진술이 바뀌는" 방식은 쓰지 않는다. 질문은 수색 1 정보·앞 직원 답변만 근거로 한다 (`dialogue.md` 심문 규칙1·2)
  - 진술 기록에는 플레이어 되묻기(C Q1·Q3·Q4의 "플레이어: …")까지 대화 형태로 쌓는다
  - "STATEMENTS n / 12"는 질문 수(4 × 3)이며 단서 개수가 아니므로 표시해도 된다
- **완료**: A·B·C 모두 끝나면 04-A(직원 면담 종합 기록) 생성 → [2차 조사 시작] 활성 (R-14). 페이지 이동은 플레이어가 누른다
- **선행 결정**: 직원 표시 정보(이름 표기 방식, 나이 표시 여부 — `characters.md`에 나이 없음), 직원 사진 에셋 (임시: 실루엣)
