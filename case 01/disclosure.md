# 정보 공개 원칙 (분리 시트)

- 규칙1: 게임은 **정보가 언제 공개되는지**가 미스터리가 되어야 한다.
- 핵심규칙: 플레이어가 진실에 접근하는 것은 허용하지만, **해당 CASE에서 예정된 정보 공개 범위를 넘어서는 확정적 정답을 얻어서는 안 된다.**
- 절대 원칙: ① 이상함은 보여준다 ② 의심은 허용한다 ③ 부분적인 추론은 허용한다 ④ 다음 챕터의 핵심 진실을 현재 챕터에서 확정하지 않는다.
- **개발자 설명과 화면 문구의 분리 (사용자 확정 D13)**: 개발자용 설명에는 정답·목적·실험 대상·최종 진실을 명시해도 된다. 단, 그 설명이 게임 화면·UI·자료명·대사·시스템 메시지로 그대로 노출되어서는 안 된다. 플레이어에게 노출되는 텍스트는 반드시 CASE별 정보 공개 단계에 맞춰 별도로 작성한다.
- **단서는 직접 말하지 않고, 추리 결과에서 확인한다 (사용자 확정 D16)**: 개별 자료는 이상함·흔적만 보여 주고 결론을 말하지 않는다. 결론은 플레이어가 조합에 성공한 뒤 추론 결과 화면이나 확인 대사로만 확인한다. 이 확인은 플레이어가 이미 도달한 정답에 대한 보상이며 새로운 비밀 공개가 아니다 (예: C07 성공 시 래미 대사 "아, 드디어 찾으셨네요. HUMAN-04.", 05-D 열람 후 C08 기록에 추가되는 전임자 = HUMAN-03 확인). 확인 시점은 플레이어가 보유한 증거에 맞춘다.
- 전체 서사: CASE 01 이상함을 발견 → CASE 02 기억을 의심 → CASE 03 기록을 의심 → CASE 04 래미의 기억을 의심 → CASE 05 비어 있는 전임자를 발견 → PAST 그 빈자리에 에드워드의 의미를 채움 → FINAL 그가 남긴 문제를 HUMAN-04가 직접 선택.

| CASE | 플레이어가 가져가는 핵심 정보 | 플레이어가 가져가는 질문 | 개발자가 아는 진짜 정보 |
|---|---|---|---|
| 01 | 사람과 기록에 이상이 있다 | 왜 기억과 기록이 다르지? | 직원들도 기억이 덧씌워진 인간 |
| 02 | 기억과 인간의 판단은 동일하지 않다 | 기억이 같아도 같은 인간인가? | MEMORY ≠ SELF |
| 03 | 과거 실험의 공식 기록이 진실과 다르다 | 최초 실험에서 실제로 무슨 일이 있었지? | 최초 실험의 은폐된 진실 |
| 04 | 래미는 자신이 알 수 없는 정보를 알고 있다 | 래미의 기억은 어디서 왔지? | 여러 인간 데이터가 래미에 혼합 |
| 05 | HUMAN-03은 비어 있는 기록으로 남아 있고 연구는 계속됐다 | 전임자에게 무슨 일이? 왜 연구는 계속됐지? | HUMAN-03은 Edward, 빈칸의 의미는 Past에서 공개 |
| PAST | 전임자의 정체와 과거 | 왜 그런 선택을 했지? | Edward의 실제 기억·사상·행동 |
| FINAL | 과거의 문제가 현재 플레이어에게 넘어옴 | 나는 어떻게 선택할 것인가? | HUMAN-04의 선택이 결말을 결정 |

**모든 단서·대사·UI 검수 질문**: "이 대사/이미지/로그를 본 플레이어가 다음 CASE의 정답을 확정할 수 있는가?" → YES라면 정보 공개 범위를 재검토한다.

## CASE 01

- "이상하다"고 느끼는 것은 허용, "진실을 안다"고 느끼게 해서는 안 된다.
- **「신입사원」 예외 (사용자 확정 D1)**: 「신입사원」에서는 **플레이어 = HUMAN-04가 성립**하고 엔딩 3종·최종 선택지를 통합기획대로 유지한다. 분리 시트의 금지 목록 중 "플레이어 = HUMAN-04"는 적용하지 않는다. SELF ARCHIVE SYSTEM은 **명칭만 금지**하고 기능·현상 표현은 허용한다 (D7, 아래 "공개 기준" 표). 그 밖의 정보 공개 원칙은 그대로 적용한다.
- **금지 정보**: A·B·C가 기억이 덧씌워진 인간 / 회사가 직원 기억에 개입 / HUMAN-03의 정체(에드워드와의 관계·과거. 전임자 = HUMAN-03은 D15·D17로 05-D 열람 후 C08 기록에서 공개 가능) / 에드워드 밀러라는 이름 / 에드워드의 과거 / 에드워드가 기억을 삭제한 이유 / SELF ARCHIVE SYSTEM이라는 명칭
- 공개 범위: 플레이어 = 자신을 신입사원으로 인식 / 회사 = 기억을 보관·관리하는 회사 / A·B·C = 연구·인사·보안 직원, 기억·기록 불일치 / CCTV = 명부에 없는 인물 존재 / HUMAN-03 = 존재했던 전임자의 흔적 / 에드워드 = 알 수 없음 / 실험 = 인간의 기억과 관련된 연구 존재 / 렘넌트 아카이브의 과거 = 일부 기록이 삭제·불완전 / 래미 = 회사 AI 비서 / 최종 목적 = 알 수 없음
- **제4의 인물·전임자·HUMAN-03의 공개 수준 (사용자 확정 D14·D15)**: CASE 01은 **"누구인가"까지만** 밝힌다. 왜 존재했는가 / 무엇을 당했는가 / 회사가 왜 그렇게 했는가는 다음 CASE로 넘긴다.
  - 개별 자료는 의심까지만 준다. 예: "이 CCTV 속 인물은 과거의 전임자와 관련이 있는 것 같다." / "전임자의 기록과 이 실험 기록 사이에 이상한 연결이 있다." / "제4의 인물이 전임자와 동일인일 가능성을 배제할 수 없다."
  - 어떤 자료도 HUMAN-03을 전임자와 직접 연결해 표기하지 않는다. 외형 비교만으로 동일인을 확정하게 하지 않는다.
  - 여러 자료를 조합한 추리(C08)에 성공하면 "제4의 인물 = 삭제된 전임자"까지 기록하고, 05-D(HUMAN-01~03 목록)를 열람한 상태가 되면 같은 C08 기록에 **전임자 = HUMAN-03**을 추가 확인한다 (D17). 확인 시점은 플레이어가 보유한 증거에 맞춘다.

## 허브·유출된 기억 화면 공개 규칙 (사용자 확정 D18)

허브와 [유출된 기억](MEMORY FILES) 화면도 검수 질문의 대상이다. 아직 플레이하지 않은 CASE의 정답이나 반전을 카드·탭·문구로 먼저 보여 주지 않는다.

- 인트로 페이지(허브)는 분위기와 한 줄 소개만 보여 주고, 세계관·사건 내용은 설명하지 않는다.
- 처음에는 PRESENT · CASE 01만 열려 있다. 현재 데모 버전에서는 [유출된 기억] 메뉴 자체가 ‘복구 중’으로 비활성이며, 나머지 CASE·파트는 잠금 표시만 한다 (D19).
- 잠긴 카드는 번호와 잠금 표시만 보여 준다(‘???’, 실루엣, 흐린 이미지 등). 제목·이미지·키워드는 해금된 뒤에 공개한다.
- 해금 직전의 CASE만 짧은 예고 문구를 둘 수 있다. 예고 문구도 검수 질문을 통과해야 한다.
- 과거(PAST)·미래(FUTURE)·FINAL 탭은 처음에는 숨기고, 조건을 채우면 나타난다. 조건은 미정 (`decisions.md` 4절).
- 열린 카드에는 진행도(본 엔딩 수, 최고 등급)만 표시하고, 엔딩 내용은 보존 기록(엔딩 수집) 규칙(R-83)을 따른다.

- 래미를 통해 **기억의 출처 문제**를 발견하는 챕터. "래미가 에드워드다"라고 결론 내리게 만들면 안 된다. "래미 안에 누군가의 기억이나 판단이 섞여 있다"까지만 도달시킨다.

- 개발자: 여러 인간 데이터 혼합 / 초기 래미 형성에 CEO 계열 데이터 영향 / 과거 정전 당시 래미 코어에 비인가 데이터 접근·전송 / 특정 인간 한 명의 데이터라고 단정할 수 없음 / Edward 데이터 가능성은 확정하지 않음 / 동일 인물로 절대 확정하지 않음
- 질문: "래미에게 섞여 있는 기억의 주인은 누구인가?" (답은 Past/Final에서 단계적으로)
