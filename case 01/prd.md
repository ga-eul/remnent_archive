## 1. 에셋 운용 원칙 (기본 토대 + 점진 교체)

현재 `인트라넷 UI/` 폴더의 이미지는 **기본 토대**다. 이후 조금씩 교체·추가하는 것을 전제로 만든다.

1. **글자를 이미지에 넣지 않는다.** 문구는 코드에서 `dialogue.md` 원문을 넣는다. 글자가 박힌 시안(`오프닝용 문구.png`, `오프닝용 문구2.png`, `독백.jpg`)은 참고용이고, 실제로는 글자 없는 틀(`오프닝용.png`, `기본 대화창.png`)과 배경(`독백 페이지.jpg`)을 쓴다.
2. **화면은 코드로 만들고 이미지는 재료로만 쓴다.** `사내 인트라넷.jpg`, `사내 메신저 창.jpg`, `사원정보.jpg`, `사원증.jpg`는 완성 시안이므로 보고 HTML로 다시 짠다. 건물 사진·아이콘·래미 얼굴 같은 재료만 이미지로 쓴다.
3. **에셋 목록 한 곳.** 화면별 이미지 경로를 에셋 목록 파일 하나에 모으고, 코드는 목록만 참조한다. 교체는 같은 이름으로 덮어쓰거나 목록 한 줄만 고친다.
4. **임시 화면 우선.** 단서 자료 이미지(03-A~06-G)·약도 그림은 미정(`decisions.md` 4절 7번)이므로 텍스트 카드·실루엣으로 먼저 만들고 나중에 교체한다. 교체해도 화면 배치가 깨지지 않게 이미지 칸의 크기를 고정한다.
5. **공통 디자인 값.** 남색 배경 + 민트색 강조, Noto Sans KR / JetBrains Mono를 인트로 허브와 함께 쓴다 (D18).

### 2단계. 오프닝·입사 — 페이지 01

- **흐름**
  1. 허브 [입사하기] → 바로 독백 (환영 알림 없음, D36). 독백 뒤 화면은 남색 배경 (바탕화면 아이콘 없음, D35)
  2. 독백: `독백 페이지.jpg` + `기본 대화창.png`. 세계관 브리핑을 플레이어 독백으로 (극 안의 정보로 전달, D18)
  3. 독백이 끝나면 고액 채용 공고 창이 바로 뜬다 → [지원하기] → 이력서(이름 필수, 비우면 ‘신입사원’) (D35)
  4. 이력서를 제출하면 사원증 만들기 창이 자동으로 뜬다 → 아바타 사진 선택 → 사원증 발급 (`사원증.jpg` 시안) (D35)
  5. 알림 "입사를 축하합니다" (`오프닝용.png` 틀 + 글자, ▶ 클릭) → 사원번호 **DA-A** 발급(디지털 기록 관리팀) → 인트라넷 접속. 입사·프로필 화면에는 ‘TEMP’를 표시하지 않는다 (TEMP는 06-D/E에서만, D24)
- **완료 기준**: 이름·아바타·사원번호 DA-A가 사원증, 사원 정보 창, My Archive, 업무 기록, 06-B, 엔딩 2·3까지 이어진다 / 화면 어디에도 ‘실험용’ 없음 (D13)
- **선행 결정**: 독백·채용 공고 원문 → `dialogue.md` 7절 (D34) / 진행 방식 → 아이콘 없이 자동으로 이어짐 (D35)
- **구현 메모** (2단계 완료, 2026-11-10)
  - 에셋: `오프닝용.png`·`독백 페이지.jpg`·`기본 대화창.png`를 `shinip/assets/img/`에 영문 이름으로 복사 (목록 `assets/assets.js`). `오프닝.jpg`는 아이콘이 그림에 들어 있어 쓰지 않고, 같은 남색을 CSS로 칠한다 (D35)
  - 공고·이력서·사원증 창에는 닫기 버튼이 없다. 다음 단계로만 이어진다
  - 알림·독백 글자는 글자 없는 틀 위에 코드로 얹는다. 사원증은 `사원증.jpg`를 보고 코드로 다시 짰다
  - 아바타 사진 4종은 `아바타/아바타-01~04.jpg`를 원형 칸에 맞게 정사각형으로 잘라 `shinip/assets/img/avatar-01~04.jpg`로 쓴다 (`assets.js`의 `AVATARS`). 사진이 없는 인물은 코드로 그린 실루엣을 쓴다
  - 이름·아바타·DA-A는 02부터 화면 머리줄에 이어서 표시. 사원 정보 창·My Archive·업무 기록·06-B·엔딩 2·3 연결은 각 화면을 만드는 3~5단계에서 확인

```
│ │문서  │ │CCTV  │ │문서  │ │
│ │출입  │ │복도  │ │업무  │ │
```

2) 단서 조합 영역
```
┌──────────────────────────────┐
│        단서 조합              │
│                              │
│  [출입 기록]    +    [CCTV]  │
│                              │
```

```
       │ 출입자 명단  │
       │ 4XXX.04.12  │
       └─────────────┘
```

- **목록**: [전체] / [문서] / [CCTV]. 획득한 단서만 카드로 보인다 (R-30). CCTV = 03-B, 05-B-VHS. 그 밖의 자료(명부·일기·면담 기록·실험 기록·로그·보고서)는 문서
- **조합**: 획득한 단서 카드 2장을 조합 영역에 드래그앤드롭(또는 [+] 클릭) → [조합하기]. 순서 무관 (R-35). 오답은 ‘연관성을 찾을 수 없습니다’, 회색 처리, 패널티 없음 (R-37). 조합 횟수 제한은 없지만 같은 두 자료 조합은 한 번만 시도 가능, tried_pairs에 있는 조합은 다시 조합할 수 없다 (R-37a, D26)
- **조합 성공**: 일반 조합 8개(C01·C04·C05·C06·C07·C08·C10·C11)의 결과가 "NEW" 카드로 해금된다 (D24·D25). 카드 내용은 `case01-logic.md` 6절 추론 결과 문장, 카드 이름은 6절 NEW 카드 이름 표(「두 자료 + 대조 기록」, R-32). C13은 일반 NEW 카드로 다루지 않고 My Archive에 저장하지 않는다. 화면 구성은 5단계 C13 최종 추론 모드(D28~D30). 엔딩 3 판정 조건에는 그대로 포함. NEW 카드는 [전체]·[단서 조합]에 들어가고(D40), 다시 조합 재료로 쓰지 않는다. 엔딩 판정 로직은 그대로. 카드에 날짜·시각이 필요하면 `4XXX.04.12 09:17` 형태
- 위 예시의 카드 이름("출입 기록", "출입자 명단")은 화면 예시이며 CASE 01 실제 자료명이 아니다
- 상단 수치 "획득 자료 n / 연결 성공 n / 현재 단계" (R-31), 총량 숨김. 홈 카드 "총 n건"도 획득 수. "연결 성공 n"은 일반 조합 8개의 성공 수이며 C13은 포함하지 않는다 (D31)
- 연결 대상: C01(튜토리얼), C04, C05, C06, C07, C08(05-D 열람에 따른 단계적 갱신, D17), C10, C11 / C13은 최종 추론 후 C13 연결 단계에서만 (그 밖의 조합은 잠금, R-51)
- 래미 관찰 기록 저장 (R-38), 최종 추론 이후에도 열람 가능

- **직원 목록**: A·B·C 세 명, 사진·이름·담당·진행 막대·상태(진행 중 / 완료 / 잠김)
- **오른쪽 순서**: 직원 정보 → 질문 버튼(Q1~Q4) → 진술 기록
  - 질문 버튼은 직원 정보 바로 아래에 고정한다. 질문을 눌러도 버튼 영역은 움직이지 않고 대화 내용에 섞이지 않는다
  - 질문을 선택하면 그 질문과 직원의 답변이 진술 기록 맨 아래에 추가된다. 이미 받은 진술은 그대로 남는다
  - 진술 기록 영역만 새 답변 위치로 자동 스크롤한다
- **규칙에 맞춘 변경 (예시와 다른 점)**
  - **순서 고정 A → B → C** (R-13): 앞 직원 완료 전에는 다음 직원 잠김. 예시처럼 아무나 고를 수 없다
  - **질문은 Q1~Q4 고정 버튼**. 예시의 "기록을 들이밀면 진술이 바뀌는" 방식은 쓰지 않는다. 질문은 수색 1 정보·앞 직원 답변만 근거로 한다 (`dialogue.md` 심문 규칙1·2)
