# 세계관 — THE HUMAN SELF PROJECT

규칙 문서 머리말: "세계관과 연출은 통합 기획 문서를 따른다."

- 게임명: **신입사원** / 세계관: **렘넌트 아카이브 (REMNANT ARCHIVE)**
- 장르: 사이버펑크 기업 인트라넷을 탐색하는 **웹 방탈출·추리 게임**
- 슬로건: **"NOTHING IS EVER LOST."** — 아무도 사라지지 않습니다. 기억만 남는다면.
- 주제: 회사는 당신을 데이터로 이해했다고 생각한다. 하지만 데이터로 이해한 당신은 정말 당신인가?
- 핵심 반전: 플레이어는 회사를 조사하고 있다고 생각하지만, 회사는 플레이어를 조사하고 있었다.

## 게임 전체 구조 (허브·파트, 사용자 확정 D18)

- 접속 첫 화면은 **인트로 페이지(허브)**다. 분위기와 한 줄 소개(라벨·제목·슬로건·부제)만 맡고 세계관을 설명하지 않는다. 세계관은 각 CASE 안에서 극 안의 정보로 전달한다.
- 허브 메뉴: [입사 지원하기] NEW HIRE · CASE 01 → CASE 01 새로 시작 / [이어서 출근하기] CONTINUE → 진행 중인 CASE 01 이어하기 / [유출된 기억] MEMORY FILES → 파트별 사건 파일 선택 / [보존 기록] RECORDS → 엔딩 수집 / [설정] SETTINGS.
- **현재 공개 범위 (데모, 사용자 확정 D19)**: PRESENT · CASE 01만 데모로 먼저 공개한다. 나머지 CASE·파트는 모두 잠금이다. 허브의 [유출된 기억]은 화면에 ‘복구 중’으로 표시된 비활성 메뉴다. ‘복구 중’은 세계관 컨셉의 표기이고, 개발상 의미는 "개발 예정"이다.
- 허브와 각 CASE는 서로의 내부를 모른다. 허브는 "새로 시작 / 이어하기"만 넘겨 CASE를 열고, CASE는 끝나면 엔딩 수집을 거쳐 허브로 돌아온다. 색·글꼴·버튼 등 공통 디자인 값은 허브와 CASE가 함께 쓴다.
- 저장은 칸을 나눈다: 게임 전체 공통(해금된 파트·CASE, 본 엔딩, 설정, CASE별 상태 status) = `remnant.global` / CASE별 진행 상태 = `remnant.present-01`(내부 ID 기준) 등. 한 CASE를 처음부터 다시 해도 그 CASE의 칸만 비운다 (R-80·R-81).
- 허브는 CASE 진행 칸의 내부를 읽지 않고, CASE가 공통 칸에 적어 둔 **status 한 단어**만 읽는다: `none`(기록 없음) / `in_progress`(진행 중) / `finished`(엔딩 판정 끝남). status는 각 CASE가 직접 바꾼다. `in_progress`일 때 새로 시작하면 확인 창을 띄우고 (R-84), `finished`이면 [이어서 출근하기]는 비활성(‘근무 종료’)이 된다 (R-85). [유출된 기억] 카드의 진행도도 공통 칸의 엔딩 기록과 status로 그린다.
- **중간 세이브 (D43)**: CASE 01은 최종 추론 직전 상태를 중간 세이브 파일로 남긴다(최대 3개). 허브 [이어서 출근하기]는 진행 중 기록과 중간 세이브를 파일 카드로 나눠 보여 준다. 이를 위해 CASE가 공통 칸에 기록 요약(`progress`·`saves`: 저장 시각·테마 이름·지점)을 적고, 허브는 이 요약만 읽는다.
- [유출된 기억]의 각 CASE 카드에는 진행도(본 엔딩 수, 최고 등급)를 표시하고, ‘처음부터 다시’는 카드 안에 둔다. 잠긴 카드·탭을 어떻게 보여 줄지는 `disclosure.md` "유출된 기억 화면 공개 규칙".

| 파트 | 구성 | 화면 표기 | 내부 ID |
|---|---|---|---|
| 현재 | CASE 1~5 | PRESENT · CASE 01 ~ 05 | present-01 ~ present-05 |
| 과거 | CASE 1~3 | PAST · CASE 01 ~ 03 | past-01 ~ past-03 |
| 미래 | FILE 1~4 | FUTURE · FILE 01 ~ 04 | future-01 ~ future-04 |
| FINAL | 1 | FINAL | final |

- 「신입사원」 = PRESENT · CASE 01 (present-01). 파트가 다르면 같은 번호를 써도 되며, 화면에서는 항상 파트 이름을 붙여 구분한다. 래미.pdf의 "과거 CASE 01" 「아이콘의 마지막 무대」는 PAST · CASE 01, 에드워드 설정룰의 PAST "CASE 02"는 PAST · CASE 02로 읽는다.

세계관 핵심 문장: 인간의 기억을 복제하는 것만으로는 인간을 대체할 수 없다. 인간을 인간답게 만드는 것은 기억이 아니라, 기억을 바탕으로 스스로 생각하고 판단하며 선택하는 능력이다. Remnant Archive는 인간의 자아를 데이터화해, 인간이 없어도 인간처럼 사고하는 새로운 존재를 만들려 한다.

| 시기 | 사업 | 내용 |
|---|---|---|
| 제1기 MEMORY PRESERVATION | 기억 보존 | 기억을 디지털 데이터로 보존해 죽음 이후에도 기억·경험 유지 |
| 제2기 HUMAN REPLICATION | 인간 대체 | 기억만으로는 같은 판단이 재현되지 않음 → 기억을 해석·선택하는 자아의 작동 원리 자체를 복제 |

**SELF ARCHIVE SYSTEM (자아 기록 시스템)** — 개발자용 명칭. 게임 화면에서는 명칭 사용 금지 (`disclosure.md`): MEMORY(과거 경험과 기억) / EMOTION(상황별 감정 반응) / VALUE(가치와 신념) / JUDGMENT(선택·판단 방식) / IDENTITY(스스로를 누구라고 인식하는지, 가장 중요)

## 정답 타임라인

게임 내 기준 날짜(오늘, 플레이어 입사일): **4XXX년 4월 12일(목)**. 시각이 필요한 기록은 `4XXX.04.12 09:17` 형태로 표기한다 (D23).

사건 4XXX.01.24 STA 03:00 (기준 날짜 4XXX.04.12 이전, D24) / CCTV 16:40 (03-B, 05-B-VHS) / 로그는 2시간마다 짝수 정시 자동 저장 (06-D/E). 03:00·16:40의 일은 다음 저장 시점(04:00·18:00) 로그에 흔적으로만 남는다.

삭제된 직원의 사번은 `RA-(삭제 코드)`. K 자살 / J 사고사 / X 처리 / H 보존. 범례는 05-D에서만 공개 (R-09b).

## 최고경영자 vs 에드워드 (FINAL의 철학적 대립)

질문: "인간을 보존한다는 것은 정확히 무엇인가?"

| | 최고경영자 | 에드워드 |
|---|---|---|
| 인간의 정의 | 기억과 행동이 지속되면 보존될 수 있다 (인간 = 기억+감정+가치+판단+정체성의 데이터) | 기억이 같아도 선택하는 주체가 다르면 같은 인간이 아니다 |
| 기억 | 보존해야 할 자산 | 인간을 이해하기 위한 흔적 |
| 데이터 | 재활용할 수 있는 자원 | 함부로 복제해서는 안 되는 개인의 일부 |
| 죽음 | 데이터로 극복할 수 있는 문제 | 죽음을 없애는 것과 인간을 보존하는 것은 다름 |
| AI | 인간의 지속성을 가능하게 하는 도구 | 인간을 대체하는 순간 인간의 의미를 훼손할 수 있음 |
| 목표 | 인간을 사라지지 않게 한다 | 인간이 자기 자신으로 존재할 수 있게 한다 |
| 방식 | 데이터의 축적·재사용·복제 | 개별 인간의 선택과 거부를 존중 |
| 최종 질문 | "기억한다면 살아 있는 것 아닌가?" | "기억한다고 해서 그 사람이 되는가?" |

HUMAN-04 실험은 이 질문에 대한 마지막 실험(‘인간을 데이터로 완성할 수 있는가?’)이다.

## 서사 핵심 구조 요약

회사에 이상이 있다 → 기억과 기록이 다르다 → 기억 연구가 존재한다 → HUMAN-01~03이 있었다 → HUMAN-04가 이어진다 → 그 대상이 나와 연결된다 → 내가 HUMAN-04였다는 사실을 추리한다 → 시스템이 이를 확인한다 → 나는 회사와 기억의 관계를 선택한다.

CASE 01의 핵심 반전은 "회사의 비밀을 발견했다"에서 끝나지 않고 "회사를 조사하던 내가 사실 회사의 실험 데이터였다는 사실을 발견했다"로 완성된다.
